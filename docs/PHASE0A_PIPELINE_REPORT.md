# Last Light: Final Graphics Reconstruction, Phase 0A Report

**The Blender asset pipeline foundation.** Branch `claude/final-art-phase0-blender-foundation`, from the accepted complete game `274d29e08f4ba1727a135f138e4e78377605059a`. Not merged into `main`.

This phase builds and proves **infrastructure only**. It contains no final art. The test figure is a deliberately plain technical probe, not a character. Every screenshot here is **software-rendered** (Chromium with ANGLE SwiftShader). Nothing was measured on a real GPU.

## 1. What was built

| Piece | Files | What it does |
|---|---|---|
| glTF loader, r160 | `dist/three-addons-gltf-loader.js`, `dist/three-addons-buffer-geometry-utils.js`, `dist/three-addons-skeleton-utils.js` | three.js r160's own `GLTFLoader` and `SkeletonUtils`, from npm `three@0.160.0`. The vendored `three.module.js` is byte-identical to that package. Only the import lines changed. Licences are recorded in `THIRD_PARTY_ASSETS.md`. |
| Asset library | `dist/asset-library.js` | Loads each `.glb` once; the bytes come from the package's embedded Blob URLs or from same-origin HTTP, never a CDN. It checks the asset id in the file and hands out copies that share geometry, materials and textures, with one skeleton per copy. Each copy has clips, shape keys, the `faces.js` expression mapping and sockets. On failure it rejects with the reason and substitutes nothing. |
| Pose bridge | `dist/asset-pose.js` | Drives a skinned skeleton from the existing `rig.js` 35-number pose contract, using the same IK and bone lengths, so existing scenes can pose authored characters. |
| Blender export | `tools/blender/ll_export.py` | The single export path, with fixed settings. It refuses to export with a wrong unit scale, unapplied transforms or unapplied modifiers. |
| Probe build | `tools/blender/build_pipeline_probe.py` → `assets/source/tst/pipeline-probe/` (`.blend`, textures, `PROVENANCE.md`) → `dist/assets/tst/tst.pipeline-probe.glb` | Builds the original test figure from nothing in Blender and exports it. Reproducible on any machine with Blender 4.2+ (verified with 5.0.1). |
| Validator | `tools/assets/validate-glb.mjs` | Runs the game's rules (ids, licence, bone and socket names, scale and orientation, budgets, shape keys, clips, texture formats, no external URIs or unsupported extensions) plus the Khronos glTF Validator. |
| DEV harness | `dist/pipeline-lab.html`, `dist/pipeline-lab-page.js`, `dist/pipeline-lab.js` | The isolated **Pipeline Lab**, using the game's renderer settings, plus the in-game `?pipeline` mode. |
| Packaging | `tools/package-playtest.mjs` | `PLAYTEST_MODELS=1` embeds every model under `dist/assets/` (the creature is always embedded) and writes `Last-Light-Pipeline-Lab.html`. Without the flag, no model is embedded. |
| Tests | `tests/pipeline-browser.mjs` | 36 checks across the lab, the running game and both offline packages. |

The only change to existing runtime code is a 3-line guarded hook at the end of `dist/game.js`: with `?pipeline` it imports the lab; without it nothing runs.

## 2. How to see it

- **Lab (served):** `python3 -m http.server 8000 --directory dist`, then open `http://localhost:8000/pipeline-lab.html`. Drag to orbit; the buttons switch views.
- **In the game (served):** `http://localhost:8000/?pipeline`. A DEV label shows what loaded; **P** moves the lineup in front of you.
- **Offline:** `PLAYTEST_MENU=1 PLAYTEST_MODELS=1 node tools/package-playtest.mjs <folder>`, then open `Last-Light-Pipeline-Lab.html`, or `Last-Light-Playtest.html?pipeline`.
- **Rebuild the probe:** `blender --background --factory-startup --python tools/blender/build_pipeline_probe.py`. Without the Blender app, `pip install bpy` (Python 3.11) and run `python tools/blender/build_pipeline_probe.py`.

## 3. The probe (`tst.pipeline-probe` v1)

Generated by Blender 5.0.1 (the `bpy` module from PyPI, headless) and exported by Khronos glTF Blender I/O v5.0.21. The file is 2,355,672 bytes.

| | |
|---|---|
| Scale | 1.555 m to the crown socket |
| Size | 11,724 triangles; 7 meshes, 12 primitives, all skinned |
| Skeleton | 35 bones: 25 deforming, 9 `socket_*`, plus `root`. Names per the Asset Plan; joint positions match `rig.js BODY` |
| Shape keys | 6: `jawOpen`, `mouthSmileLeft`, `mouthSmileRight`, `browInnerUp`, `eyeBlinkLeft`, `eyeBlinkRight` |
| Materials | 9 PBR: skin and shirt with base colour, normal and ORM maps; shorts and hair with base colour and normal maps; a metallic watch; eyes, iris, mouth, shoes |
| Textures | 10 images, 512² (colour maps JPEG, data maps PNG) |
| Clips | `idle_breathe` 2 s, `walk_normal` 1 s, `wave_r` 1.5 s, and `talk` 2 s (bone and shape-key Actions merged into one clip) |

Validator result: **0 errors**. Khronos glTF Validator 2.0.0-dev.3.10 reports 0 errors and 7 warnings, all `NODE_SKINNED_MESH_NON_ROOT`. That warning is Blender's normal layout (meshes under an identity armature node) and is harmless. Report: [qa/pipeline-phase0a/validate-tst.pipeline-probe.json](qa/pipeline-phase0a/validate-tst.pipeline-probe.json).

## 6. Problems found and fixed during the phase

1. The head lost its UVs. Blender's `bmesh` `calc_uvs` needs a UV layer to exist first. The Khronos validator caught it (5 errors), and it was fixed in the build script.
2. The facial clip was not exported. A separate shape-key Action got renamed `talk.001`. It now uses Blender 4.4+ slotted Actions: one Action with a Key slot, plus an NLA strip on the Key.
3. Every skinned primitive got its own Skeleton and bone texture (48 for 4 copies). The library now shares one skeleton per copy (4).
4. The pose bridge was 2.5 cm off at the wrists, because the torso pivoted at `spine_01` while `rig.js` pivots it at the pelvis. Fixed; the error is now 0.
5. The eyes were inside the head, and the skin normal map was far too strong. Both fixed. The lab cameras were also moved in front: figures correctly face the game's −Z, like the procedural kid beside them.

## 7. Ready, and still unverified

**Ready:**

- Blender → `.glb` export with fixed, checked settings.
- Multiple PBR materials with normal and roughness/metal maps.
- Skins and skeletal clips.
- Shape keys and facial clips.
- Correct scale and orientation.
- The plan's bone and socket names.
- The existing pose contract driving an authored skeleton.
- `faces.js` expressions driving shape keys.
- Loading once and placing many copies.
- The served game, and the offline package with zero network requests.
- A validator, and a handoff document for Astra.

**Unverified or not done:**

- **A real GPU.** Every frame and timing here is software rendering. FPS and GPU memory with authored characters are unmeasured.
- The **Blender application GUI**, and Blender **4.2/4.5**. Only Blender 5.0.1 as a headless module ran. The script has 4.2-compatible branches, but they are untested.
- A **final-quality character's** cost (35–45k triangles, 2048² textures, 30–50 shape keys, fingers). The probe is about a quarter of that budget.
- **Environment map.** The game has none, so authored metal and glossy surfaces lack reflections (decision A-47).
- **Hand and foot contact** for authored characters. `socket_grip` sits 3.9 cm from the bar and the ball of the foot 8 cm from the pedal under the current `ridePose` targets (decision A-48).
- The **person facade** that lets story scenes swap a procedural person for an authored one: `physical.js` frames, `person.joints`, visibility and shadows (Phase 1).
- **Per-character limb lengths**: the bridge uses one `BODY`.
- **Lip sync** to visemes, and Chapter Eight's crying channels.
- **KTX2/meshopt compression** and **LODs**.
- The probe's `eyeBlink` keys only drop the skin above the eye. It has no eyelid geometry, so it does not show a real blink.
- **Export determinism.** JSON, vertices, textures and clips repeat exactly, but the triangle index order in a few primitives varies between exports.
- `tests/main-menu-browser.mjs` on the package (see §5).
